# PCネットワークモニター MVP仕様

## 1. 目的

Windows PCが現在使用しているインターネット接続について、OBS Browser Source上で次の情報を継続的に確認できるようにする。

- 使用中NICの接続状態とリンク速度
- インターネットへの遅延
- 直近60秒のジッター
- ICMP利用時のパケット損失率
- HTTPフォールバック時のリクエスト失敗率
- 直近60秒の遅延推移

本MVPでは測定値をそのまま提示し、回線品質の良否をアプリケーション側では判定しない。

## 2. 対象範囲

### 対象

- Windows
- ローカルPC上で動作する単一のモニタープロセス
- OBS Browser Sourceまたは通常のブラウザからの表示
- IPv4によるインターネット疎通監視
- 現在の経路に応じたNICの自動追従

### 対象外

- ONLINE / DEGRADED / OFFLINEなどの総合状態判定
- LAN内やデフォルトゲートウェイまでの品質測定
- 複数NICの同時表示
- 通信量、帯域使用率、累積送受信量
- IPv6
- 測定結果の永続保存
- 外部サーバーへのテレメトリー送信

## 3. 既定設定

実行ファイルと同じディレクトリにある任意の `config.json` を起動時に1回読み込む。ファイルが存在しない場合は以下の既定値を使用する。

```json
{
  "icmpTarget": "8.8.8.8",
  "httpTarget": "https://www.google.com/generate_204"
}
```

設定の再読み込みはMVPの対象外とする。設定値が不正な場合は既定値へ暗黙に戻さず、原因をログへ出力して起動を中止する。

### 検証ルール

- `icmpTarget`: IPv4アドレスまたはIPv4へ名前解決できるホスト名
- `httpTarget`: `https` URL
- 未知のJSONフィールド: エラー
- 空文字: エラー

## 4. 使用中NICの選択

ICMP測定先へ到達するためにWindowsが選択する経路から、使用中NICを特定する。単純な「接続済みNICの先頭」ではなく、実際のルーティング結果を基準とする。

これにより、Ethernet / Wi-Fiの切り替えやVPN経路を反映する。経路とNIC情報は定期的に再評価し、変更時は表示へ自動反映する。

表示するNIC情報:

- NICの表示名
- 接続状態
- 送受信リンク速度
- インターフェース識別子

リンク速度は実効スループットではなく、Windowsが報告するNICのリンク速度である。送信と受信で値が異なる場合はそれぞれ表示する。

WindowsネイティブAPIを利用し、PowerShellや外部コマンドの出力解析には依存しない。

## 5. 測定方式

### 5.1 ICMP

通常はWindowsのICMP APIを使用し、1秒間隔でEcho Requestを1回送信する。管理者権限や `ping.exe` には依存しない。

各測定は次を記録する。

- 測定方式
- 測定先
- 成否
- 成功時のRTT
- 測定時刻

### 5.2 HTTPフォールバック

ICMPが3回連続で失敗した場合、HTTP測定先へ確認リクエストを送る。

- HTTPが成功した場合: ICMPが利用できないと判断し、HTTP測定へ切り替える
- HTTPも失敗した場合: インターネット疎通失敗としてICMP測定の失敗に計上する
- HTTP測定中: 30秒ごとにICMPを再確認し、成功したらICMPへ戻す

HTTPの応答時間にはDNS、TCP、TLSおよびHTTPサーバーの処理時間が含まれるため、ICMP RTTと同一の値として比較しない。測定方式を画面へ常に表示する。

測定方式が切り替わったときは統計履歴をリセットし、異なる意味の測定値を同一集計へ混在させない。

## 6. 統計値

統計は現在の測定方式による直近60回（通常は約60秒）の測定結果から算出する。

### 遅延

直近の成功した測定のRTTをミリ秒で表示する。成功値がまだない場合は値なしとして表示する。

### ジッター

時間的に連続した成功測定について、隣接RTTの絶対差の平均を使用する。

```text
jitter = sum(abs(rtt[i] - rtt[i-1])) / 有効な隣接ペア数
```

測定失敗を挟むサンプル同士は隣接ペアに含めない。有効なペアがない場合は値なしとして表示する。

### パケット損失率

ICMP測定時に表示する。

```text
packetLoss = 失敗したICMP測定数 / 全ICMP測定数 * 100
```

### HTTPリクエスト失敗率

HTTP測定時に表示する。これはパケット損失率ではないため、画面上のラベルを切り替える。

```text
requestFailure = 失敗したHTTP測定数 / 全HTTP測定数 * 100
```

## 7. データ収集と配信

測定はブラウザ接続ごとに開始せず、アプリケーション内の共有モニターが1系統だけ実行する。

共有モニターは次を担当する。

1. 使用中NICの再評価
2. ICMP / HTTP測定
3. 60サンプルの履歴管理
4. 統計値の計算
5. 最新スナップショットの生成

WebSocketクライアントは共有モニターの最新スナップショットを受信する。ブラウザ接続数が増えても外部への測定回数は増加しない。

スナップショットには少なくとも次を含める。

- NIC情報
- 測定方式と測定先
- 最新の遅延
- ジッター
- パケット損失率またはHTTP失敗率
- 直近60回の時刻、成否、RTT
- スナップショット生成時刻

## 8. UI

OBS Browser Sourceで判読できるコンパクトな表示とする。

表示項目:

- NIC名
- 接続状態
- 送信 / 受信リンク速度
- 測定方式
- 測定先
- 最新遅延
- ジッター
- パケット損失率またはHTTPリクエスト失敗率
- 直近60秒の小さな遅延折れ線グラフ

グラフでは測定失敗を0 msとして描画せず、欠損として表示する。総合状態の文言や、閾値に基づく良否の色分けは行わない。

WebSocketが切断された場合は既存画面を消さず、データ更新が停止していることを判別できる表示にする。再接続後は最新スナップショットへ更新する。

## 9. エラー処理

- 使用可能な経路またはNICがない場合、NICを未接続として表現し、プロセスは継続する
- 一時的な測定失敗でプロセスを終了しない
- 設定不備は起動時エラーとする
- WebSocketクライアントの切断は測定処理へ影響させない
- 測定およびNIC取得のエラーは、継続運転を妨げない範囲でログへ記録する

## 10. テスト方針

Windows Quality Gateで少なくとも次を検証する。

- 設定ファイルなし、正常値、不正値
- 60サンプルのリングバッファ
- 遅延、ジッター、損失率、失敗率の計算
- ICMPからHTTP、HTTPからICMPへの状態遷移
- 測定方式切り替え時の履歴リセット
- WebSocketスナップショットのJSON形式
- Windows向け実行ファイルのビルド

Windows APIと外部通信はインターフェースで分離し、単体テストではテストダブルへ置き換えられる構造にする。

## 11. 受け入れ条件

1. Windowsで通常ユーザー権限のまま起動できる
2. 設定なしでGoogleを既定測定先として動作する
3. `config.json` でICMPとHTTPの測定先を変更できる
4. 現在の経路で使用されるNICを自動表示する
5. NICまたは経路の変更へ自動追従する
6. 1秒間隔で測定し、直近60回から統計を算出する
7. ICMPが利用できずHTTPは利用できる場合、自動的にHTTPへ切り替わる
8. HTTP測定中にICMPが回復した場合、自動的にICMPへ戻る
9. 測定方式に応じてパケット損失率とHTTP失敗率を正しく区別する
10. 数値と60秒の遅延グラフをOBS Browser Sourceで表示できる
11. ブラウザ接続数にかかわらず測定処理は1系統だけ動作する
12. 総合的な回線品質判定を表示しない
