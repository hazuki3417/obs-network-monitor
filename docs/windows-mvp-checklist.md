# Windows MVP 手動確認チェックリスト

自動テストでは再現しにくいNIC切り替え、実ネットワークのICMP制御、OBS表示をWindows PCで確認するためのチェックリストです。実施日、Windows・OBSのバージョン、使用したコミットまたは成果物名を記録してください。

## 事前準備

- [ ] Windows 10またはWindows 11の64-bit PCを用意した
- [ ] 管理者として起動していないPowerShellまたはコマンドプロンプトを使用している
- [ ] `obs-network-monitor-windows-x64.zip` を展開した、または対象コミットからexeをビルドした
- [ ] OBS Studioと通常のWebブラウザを利用できる
- [ ] 他のプロセスが `127.0.0.1:8080` を使用していない

## 1. 設定なし・通常ユーザー起動

1. exeと同じフォルダーに `config.json` がないことを確認する。
2. 非昇格のPowerShellから `./obs-network-monitor.exe` を実行する。
3. ブラウザで `http://127.0.0.1:8080/` を開く。

- [ ] 管理者権限を要求されずに起動した
- [ ] パネル、NIC情報、リンク速度、測定先が表示されない
- [ ] 遅延、ジッター、失敗率が更新された
- [ ] 約1秒ごとに遅延グラフと通信量グラフが更新された

## 2. 有効な設定

1. `config.example.json` を `config.json` へコピーする。
2. `icmpTarget` と `httpTarget` を利用環境で到達可能な測定先へ変更する。
3. アプリを再起動する。設定は起動時にだけ読み込まれる。

- [ ] 設定した測定先に対する遅延測定が継続した
- [ ] `icmpTarget` にIPv4アドレスとホスト名のどちらも指定できた
- [ ] `httpTarget` にHTTPS URLを指定できた

## 3. 不正な設定

次の各ケースを1つずつ `config.json` に設定して起動する。

- 未知のフィールドを追加する
- 測定先を空文字にする
- `httpTarget` をHTTP URLにする
- 壊れたJSONにする

- [ ] 各ケースでプロセスが起動を中止した
- [ ] コンソールに `load config` と原因が表示された
- [ ] 不正値が既定値へ暗黙に置き換わらなかった

## 4. NIC・経路切り替え

1. EthernetとWi-Fiなど、2つの利用可能な経路を用意する。
2. アプリ実行中にWindowsの優先経路を切り替える。
3. VPNを利用する場合は、接続・切断でも同じ確認を行う。

- [ ] 実際にインターネット通信へ使われるNIC名へ自動追従した
- [ ] 接続状態とリンク速度が新しいNICの値へ変わった
- [ ] 切り替え中の一時エラーでプロセスが終了しなかった

## 5. ICMP / HTTP切り替え

ICMPを返さない検証用ネットワークまたは測定先を使い、HTTP測定先は到達可能な状態にする。予約済みTEST-NETアドレス `192.0.2.1` は外部へ到達しないICMP測定先の例として利用できる。

- [ ] ICMPが3回連続失敗した後、方式表示がHTTPへ変わった
- [ ] HTTP時の指標名が `REQUEST FAILURE` になった
- [ ] 切り替え時に履歴とグラフがリセットされた
- [ ] ICMPを再び利用可能にできる環境では、30秒以内の再確認後にICMPへ戻った
- [ ] ICMP時の指標名が `PACKET LOSS` に戻った

## 6. 複数クライアントと再接続

1. 通常ブラウザを2つ開き、同じURLを表示する。
2. OBSにも同じBrowser Sourceを追加する。
3. exeを終了し、ページを閉じずに再起動する。

- [ ] 3クライアントで同じ測定値が更新された
- [ ] クライアントを閉じても他の画面とプロセスが継続した
- [ ] exe停止後も既存値が画面に残った
- [ ] exe再起動後、自動的に最新値の更新が再開した

## 7. OBS Browser Source

1. OBSで「ブラウザ」ソースを追加する。
2. URLを `http://127.0.0.1:8080/`、幅と高さを `480` にする。
3. OBSのシーンを切り替え、ソースを再表示する。

- [ ] `LATENCY` と `NIC TRAFFIC` の数値とグラフを判読できた
- [ ] 遅延統計のラベル、値、単位が列ごとに揃って表示された
- [ ] パネル、NIC情報、リンク速度、グラフタイトル、グラフ下部ラベルが表示されない
- [ ] 左側目盛り、右上の単位付き上限値、滑らかな曲線が表示された
- [ ] 背景の透明部分がOBS上で保持された
- [ ] シーン再表示後にWebSocketが接続し、最新値へ復帰した
- [ ] 画面に総合的な回線品質判定や閾値色分けがない

4. URLを `http://127.0.0.1:8080/?sections=latency`、サイズを480 x 270に変更する。
5. URLを `http://127.0.0.1:8080/?sections=traffic`、サイズを480 x 210に変更する。

- [ ] `sections=latency` では遅延セクションだけが表示された
- [ ] `sections=traffic` ではNIC通信量セクションだけが表示された

6. URLへ `?parts=values`、`?parts=graph`、`?parts=values,graph` を順に指定する。
7. `?sections=traffic&parts=graph` のように `sections` と併用する。

- [ ] `parts=values` では数値だけが表示された
- [ ] `parts=graph` ではグラフだけが表示された
- [ ] `parts=values,graph` と未指定では両方が表示された
- [ ] `sections` と `parts` の指定が同時に反映された
- [ ] データ未取得時もグラフ中央に待機テキストが表示されなかった
